# 奖励系统八类问题修复与回归

2026-09-14：此前 10 条失败对应的 8 类问题已修复。最新奖励回归 **269 项通过、0 项失败**，包含真实 Unity Play 模式；以奖励处理日期计冠的规则保留。

## 修复内容

| 问题 | 修复后的行为 |
|---|---|
| 内部去重历史暴露 | 服务端为 SignalR 和 MVC 注册专用进度 JSON 转换器，只输出公开字段。MongoDB 仍保存完整 ProcessedRoundIds，未清空数据库历史，也未给 Unity 公共模型新增依赖 |
| 旧数据 RoundIds=null | 使用空列表恢复，并将修复写回数据库；保留既有进度和可用历史，后续重复回调仍防重 |
| 通知失败打断结算 | 奖励成功提交后，缓存失效通知失败只记录警告；钱包数据仍以服务器查询为准 |
| 奖励失败留下半登录状态 | 当天奖励处理完成后才登记连接的认证状态；奖励写入失败时连接保持未认证，同一连接可以重新登录 |
| 奖励存储异常打断小局 | 以相同小局键和结算时间最多尝试三次，短暂故障可恢复；持续失败记录错误后继续推进正常小局、比分和胜者 |
| 配置累计金额溢出 | 以 long 校验总和不超过 int.MaxValue，且在创建钱包或发奖之前加载并校验配置；同时拒绝 null 配置/档位 |
| 刷新期间奖励通知遗漏 | 进行中的强制刷新会排队一次后续读取，连续通知合并；返回任务覆盖后续读取，账号切换使旧队列失效 |
| 登录后没有任务入口 | Game 场景加载时从未激活的 EditorInfo 获取主菜单引用并初始化任务组件；初始化幂等，之后打开卡组编辑器不会新增重复组件或按钮 |
