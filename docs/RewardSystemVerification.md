## 发现并修复的问题

Windows PowerShell 5 通过独立 `powershell.exe -File` 执行管理员脚本时，默认 Mongo shell 路径解析失败，实际发奖没有执行。已把路径解析从参数默认表达式移到参数声明之后，并校验可执行文件存在。修复后，重复发奖、并发发奖、离线指定账号发奖及最大金额测试均通过。

此前失败运行保留在 `work/RewardSystem/`，不计入通过结果：启动宿主配置错误、选中已断开的网卡地址、上述管理员脚本错误，以及新增 Unity 测试脚本尚未被编辑器加载导致的界面等待超时。测试结果只有完整运行结束且全部断言成功才标为通过。

## 复跑方式

从仓库根目录运行；需要本机已安装的本地 .NET / MongoDB 工具。先编译测试项目，再执行脚本：

```powershell
$env:DOTNET_MULTILEVEL_LOOKUP = '0'
Push-Location work/LocalServer
./dotnet/dotnet.exe build ../../src/Cynthia.Card/test/RewardSystemTest/RewardSystemTest.csproj -p:BuildProjectReferences=false --no-restore
Pop-Location
./scripts/Test-RewardSystem.ps1
```

测试脚本默认选择具有默认网关的活动网卡，也可传 `-LanAddress` 指定本机地址。服务端源代码改变后，应先重新编译服务端；这里的 `BuildProjectReferences=false` 用于避免覆盖正常本地服务正在加载的 DLL。

每次运行新建证据和数据库目录，`work/RewardSystem/latest.json` 指向最近一次运行。脚本只清理自己启动且路径匹配的测试进程；保留磁盘证据。
