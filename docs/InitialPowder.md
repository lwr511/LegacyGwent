# 初始星尘发放

服务端配置：`src/Cynthia.Card/src/Cynthia.Card.Server/InitialPowder.json`。

```json
{
  "Amount": 5000
}
```

## 规则

- 已有账号：服务器启动后后台扫描全部账号，包括离线账号，在已有余额上加上配置数量。例如原有 70，发放后为 5070。
- 新账号：注册成功返回前发放；登录、查询收藏、每日任务、合成入口也检查漏发。
- 每个账号只领取一次。消费后不会自动补满，重复登录、服务器重启、多个服务器同时补发都不会重复发。
- 每日登录的 10 星尘独立计算，因此全新账号首次登录通常显示 5010。
- 发放不改变卡牌拥有权、普通/闪卡选择、每日任务进度或其他奖励记录。

## 修改数量

开发环境修改上述源文件，重新构建并重启服务器。发布包中修改与 `Cynthia.Card.Server.dll` 同目录的 `InitialPowder.json`，然后重启服务器。文件会随 build/publish 输出。

`Amount` 必须是 0 到 1000000000 的整数。0 表示暂停发放，不消耗未领取账号的资格。缺失文件、缺失字段、非法类型、负数或超范围会阻止服务启动，避免悄悄使用错误金额。

**修改金额仅影响未领取账号。** 已经领过的账号不会补差额、扣回或重发。如果测试完决定换金额，正式服首次部署前修改即可；若需要对已经领取的人再次补发，这是独立运营活动，应使用独立发放编号和审核过的金额。

## 数据和可靠性

真实数据库为 `gwentdiy`，钱包集合为 `premium_collection`。领取凭证复用 `Rewards`，固定 `RewardId` 为 `initial-meteorite-powder-v1`，记录实际到账额和 UTC 时间。不要因调数值而改这个编号，也不要清理该凭证，否则会恢复领取资格。

以账号 ID 和“未存在领取凭证”为条件，在同一条 MongoDB 原子更新中增加余额、递增 Revision、写入凭证，并使用 majority 写确认。与每日奖励及合成扣款并发时不会用旧余额覆盖新余额。

后台分批读取账号 ID，不一次性加载全部账号。失败账号会记录日志，其余账号继续；有失败时 30 秒后重新扫描，已经成功的账号跳过。服务停止取消扫描；下次启动仍可继续。异常余额导致溢出时拒绝到账且保留领取资格。

注册数据和钱包是两个集合：若注册用户写入成功后数据库故障，调用可能返回错误，但已创建的账号仍可在恢复后的登录或下一次启动补发中领取。不会为不存在的账号创建领取资格。当前协议没有新增客户端发钱接口。
