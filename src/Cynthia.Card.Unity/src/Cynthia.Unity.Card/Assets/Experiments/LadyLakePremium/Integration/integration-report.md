## 2. Worker interface used by the assembler

`Build()` resolves both builders by reflection over `AppDomain.CurrentDomain.GetAssemblies()` and
invokes a public static parameterless `Build()`:

* `LegacyGwent.LadyLakePremium.Editor.LadyLakeModelBuilder.Build()` →
  `Assets/Experiments/LadyLakePremium/Model/FigureRig.prefab`
* `LegacyGwent.LadyLakePremium.Editor.LadyLakeEnvironmentBuilder.Build()` →
  `Assets/Experiments/LadyLakePremium/Environment/Environment.prefab`
  (+ `Environment/Audio/LadyLakeLoop.wav`)

If a type/method is missing, or the expected prefab does not exist afterwards, `Build()` throws an
`InvalidOperationException` naming the exact missing type, file and expected path. There is no
placeholder/fallback geometry.

## 3. Assembly: `Card/Pivot`

```
Card                     (prefab root, local 0)
└─ Pivot                 local (0.053175, -2.042541, 0)
   ├─ FigureRig          (nested prefab instance, local 0)
   └─ Environment        (nested prefab instance, local 0)
```

Both worker prefabs are nested prefab instances (`PrefabUtility.InstantiatePrefab`), so their own
asset references (meshes, bones, clips, materials, audio) are preserved and remain editable in
`Model/**` and `Environment/**`. The pivot rotation therefore turns the whole authored scene
(figure + sword + waterbed + foliage) together, exactly like a source premium scene's `Pivot`.

`catalog-entry.json` uses `"pivot": "Pivot"`, which `DynamicCardView.Create` resolves with
`model.transform.Find("Pivot")`.

## 4. Exact framing math (unchanged production `ArtRegion`)

`DynamicCardView` always renders the source prefab in a **square** RenderTexture and samples the
original `DynamicCardFraming.ArtRegion` into the 497×713 card window. Integration does **not**
override that rectangle; it only positions the contract-space content so the 497×710 painting
(world 4.97 × 7.10) lands inside it.

Camera (from the catalog entry): `fieldOfView = 35`, `cameraDistance = -11.5`, `nearClip = 1`,
`farClip = 300`; `DynamicCardFraming.Apply` forces `aspect = 1`.

```
halfHeight   = |cameraDistance| * tan(FOV/2)
             = 11.5 * tan(17.5 deg)
             = 11.5 * 0.31529879
             = 3.62593617
fullHeight   = 7.25187235                 (== fullWidth, square RT)

ArtRegion    = (x .16602942, y .0035620682, w .68260696, h .98114324)
regionWorldH = .98114324 * 7.25187235 = 7.11513360   -> 7.10-high painting FITS
regionWorldW = .68260696 * 7.25187235 = 4.95017834   -> 4.97-wide painting clips 0.4%
regionCentre = (u .50733290, v .49413369)
dx           = (u - 0.5) * fullHeight =  0.05317502
dy           = (v - 0.5) * fullHeight = -0.04254091
```

`DynamicCardView` parents the prefab under `Source appearance anchor` at **(0, +2, 0)** while the
card camera stays on the staging axis, so the pivot must also remove that offset:

```
Pivot.localPosition = (dx, dy - 2, 0) = (0.053175, -2.042541, 0)
```

This is the required *"appearanceoffset+2"* adjustment: without it the card sits 2 world units high
and the painting is cropped at the top. The only residual deviation is the 0.4 % horizontal crop
that is inherent to the production `ArtRegion` aspect (7.1151 world high / 4.9502 world wide) versus
the 497×710 painting aspect; fitting by height (the required *"world 7.1 high image fits"*) is
preserved exactly. `LadyLakePremiumValidator` recomputes and checks these numbers.

Verified source convention for comparison: the shipped `56180101/Card.prefab` hierarchy is
`Card (0,0,0) -> 56180101 (0,0,0) -> Pivot (0,-2,0) -> model`, i.e. source packs put the pivot at
exactly `(0,-2,0)` to cancel the `+2` appearance anchor and centre their content on the camera axis.
That centres the content in the whole square RT; the production `ArtRegion` is not exactly centred
(v centre `.49413369`), so a 7.10-high centred painting loses ~3.5 px at the top. This integration
adds the small region-centre correction `(+0.053175, -0.042541)` so the full 497×710 painting fits
the unchanged `ArtRegion` (the requirement) while keeping the `-2` anchor compensation.

## 5. Runtime path — real production code, nothing cloned

`LadyLakePremiumStage.Build()` performs, in order:

1. obtains the **real collection `ArtCard`** (serialized instance written by the builder, or
   `Resources.Load("Prefab/Cards/ArtCard")` fallback);
2. applies the original serialized gold border / neutral gold faction icon, strength 25 and hides
   the rules/name banner (`Content`) so only the complete framed card is shown — **no debug text**;
3. `DynamicCardPresentation.Configure(CardBorder, Content)` exactly as `ArtCard.SetCard` does;
4. enables `DynamicCardSettings` for the scene only and restores the previous tier in `OnDestroy`;
5. calls the one production entry point:

```csharp
DynamicCardView.Bind(card.CardImg, "c10000000",
    concealed: false, largePreview: true,
    wholeCard: card.CardBorder.rectTransform, listThumbnail: false,
    playPreviewAudio: true,
    presentationRoot: (RectTransform)card.transform,
    portraitBorder: card.CardBorder.rectTransform,
    premium: true);
```

Everything else is production: the isolated scene, staging cell, `Card camera`, square
RenderTexture, `DynamicCardFraming.Apply`, Animator `Rebind/Update`, particles, material/property
blocks, `DynamicCardEffects`, `DynamicCardSourceControllers`, idle sway, drag
(`DynamicCardDragHandle`) and the 55° entrance curve. **No custom RenderTexture backend, no cloned
player/camera/drag code.** `playPreviewAudio` defaults to `true` so the 12 s environment loop is
audible; set it to `false` for exact parity with `ArtCard.SetCard` (hover detail), while
`CardShowInfo` (grid) also uses `true`.

The static `c10000000` sprite stays on `CardImg` and remains visible until (and if) the dynamic
frame is ready.

UI layout follows the old standalone wrapper's reference layout (backdrop, stretched `CardHost`,
card centred, `cardHeightFraction = .72`, 1600x900 scaler) but uses a **Screen Space - Overlay**
canvas instead of a second presentation camera: `DynamicCardPresentation` already supports overlay
canvases with its 35° projective divide, and the only camera in the scene is the one
`DynamicCardView` creates for the card RenderTexture. `CardBorder` receives the production
`DynamicCardDragHandle` from `Bind`, so dragging is the real behaviour.

## 6. ⚠ Bundled cache vs source fallback (requires root)

Verified from the shipped code:

* `DynamicCardLibrary.LoadCatalog()` (editor) first tries
  `Library/DynamicCardsBundles/StandaloneWindows64/cards.bundle` + `.editor-ready`. **That cache
  currently exists in this checkout** (`cards.bundle`, `cards.bundle.editor-ready`, `cards.index.json`).
* The AssetDatabase source fallback (`AllowEditorSourceLoading` → `AssetDatabase.LoadAssetAtPath(entry.prefab)`)
  is only reached inside `if (bundle == null)`. **A ready bundle therefore wins and the fallback is
  never consulted.**
* `Assets/DynamicCards/Content/catalog.json` does **not** contain `c10000000` or
  `lady-lake-authored` yet.

Consequence: **merging the catalog entry alone is not enough while the cache exists.** Play will
show only the static painting (the designed fallback) and log the warning emitted by
`LadyLakePremiumStage.LateUpdate`.

Root steps (documented, none performed here; the cache was not moved or deleted):

1. Merge `Integration/catalog-entry.json` (a single `DynamicCardEntry`) into
   `Assets/DynamicCards/Content/catalog.json` `cards[]`, keeping `artIds: ["c10000000"]` unique.
2. **Relocate the prefab path.** `DynamicCardBundleBuilder.Build()` rejects any catalog prefab that
   is not under `Assets/DynamicCards/Content/Latest/` (or the two `Old/` source roots):
   *"Premium scenes must use an explicit supported source directory."* So root must copy
   `Integration/Card.prefab` to a supported directory — e.g.
   `Assets/DynamicCards/Content/Latest/ladylake/Card.prefab` — and rewrite the catalog `prefab`
   to that path. Dependencies (`FigureRig.prefab`, `Environment.prefab`, meshes, materials,
   controllers, `LadyLakeLoop.wav`) are pulled in by `AssetDatabase.GetDependencies`, so they may
   stay under `Assets/Experiments/LadyLakePremium/`. Alternatively root may widen the guard (a
   production edit that is out of scope for this worker).
3. Rebuild the packages: `Tools > Dynamic Cards > Build Options` (or
   `DynamicCardBundleBuilder.Build(target)`). The 12 s `intro/loop` clips of `FigureRig` must appear
   as `.controller` dependencies so `ExpectedControllers` matches (`DynamicCardLibrary.OpenPart`).
4. Re-enter Play Mode so `LoadCatalog` re-reads the rebuilt bundle.

If root deliberately wants the AssetDatabase fallback instead, the ready bundle must be absent for
that editor session; deleting/renaming the cache is **not** part of this deliverable and was not
done. `DynamicCardSettings` is only toggled inside the scene and restored on destroy; no other
`PlayerPrefs`/`EditorPrefs` value is changed.

## 8. Editor file bridge (opt-in)

`LadyLakePremiumEditorBridge` (`[InitializeOnLoad]`) polls `Integration/editor-request.txt` once per
second. It does **nothing** while the file is absent, empty or starts with `#`; it never rebuilds
and never enters Play Mode on its own.

Write exactly one command per trigger:

| Command | Action |
|---|---|
| `build` | `LadyLakePremiumBuilder.Build()` (edit mode only) |
| `open` | open `Integration/LadyLakePremium.unity` |
| `play` / `stop` | toggle Play Mode |
| `capture [path]` | `ScreenCapture.CaptureScreenshot` (Play Mode only, default `Integration/capture.png`) |
| `validate` | regenerate `validation-report.json` |
| `sample` | write `Integration/stage-sample.json` from `LadyLakePremiumStage.Describe()` |
| `status` | refresh `editor-state.json` only |
| `refresh` | `AssetDatabase.Refresh()` (force a script compile before `build`) |

Results: `Integration/editor-result.txt`, `Integration/editor-state.json`,
`Integration/stage-sample.json`. Root drives the bridge; this worker issued no editor requests.
